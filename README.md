## 1. Objective

The objective of this assignment is to consume streaming food-delivery data from an Apache Kafka topic, store the consumed data in MySQL, and analyse the data using a Grafana dashboard.

The dashboard provides visibility into order volume, order status, revenue contribution, delivery delays, and on-time delivery performance.

---

## 2. Project Overview

This project is based on a food-delivery and online food-ordering use case.

The streaming data is generated and published to Kafka. A Python consumer subscribes to the Kafka topic and stores the consumed events in a MySQL database. Grafana is then connected to MySQL to analyse the stored data through interactive visualisations.

7. Grafana Dashboard
Dashboard Name
SDA Assignment 3 — Food Delivery Analytics

Grafana is connected to the MySQL database and uses SQL queries to analyse the consumed food-delivery data.
The dashboard contains five panels.
Panel 1 — Total Orders
Visualisation
Stat
Purpose
Shows the total number of food-delivery orders consumed and stored in the database.
SQL Query
SELECT COUNT(*) AS total_orders
FROM food_delivery_events;

Panel 2 — Orders by Status
Visualisation
Bar Chart
Purpose
Shows the distribution of orders across different order statuses.
SQL Query
SELECT
    order_status,
    COUNT(*) AS orders
FROM food_delivery_events
GROUP BY order_status
ORDER BY orders DESC;

The panel shows the volume of orders in different stages such as Completed, Confirmed, Out for Delivery, Preparing, Cancelled, and Placed.
Panel 3 — Revenue Contribution by Food Category
Visualisation
Pie Chart
Purpose
Shows the contribution of different food categories to total order revenue.
SQL Query
SELECT
    food_category,
    SUM(order_value) AS total_revenue
FROM food_delivery_events
GROUP BY food_category
ORDER BY total_revenue DESC;

This allows comparison of revenue generated by different food categories.
Panel 4 — Delayed Orders: Distance vs Delay & Order Value
Visualisation
XY Chart
Purpose
Analyses delayed orders by comparing delivery distance, delivery delay, and order value.
SQL Query
SELECT
    delivery_distance AS distance_km,
    (actual_delivery_time - estimated_delivery_time) AS delay_minutes,
    order_value AS order_value
FROM food_delivery_events
WHERE actual_delivery_time > estimated_delivery_time
  AND delivery_distance IS NOT NULL;

This analysis helps identify the relationship between delivery distance and delays while also considering the value of delayed orders.
Panel 5 — On-Time Delivery Rate
Visualisation
Gauge
Purpose
Shows the percentage of deliveries completed within the estimated delivery time.
SQL Query
SELECT
    100.0 * SUM(
        CASE
            WHEN actual_delivery_time <= estimated_delivery_time
            THEN 1
            ELSE 0
        END
    ) / COUNT(*) AS on_time_percentage
FROM food_delivery_events
WHERE actual_delivery_time IS NOT NULL
  AND estimated_delivery_time IS NOT NULL
  AND actual_delivery_time > 0
  AND estimated_delivery_time > 0;

The metric provides an operational view of delivery performance.
8. Business Insights
The dashboard provides several actionable insights for a food-delivery business.
First, the order-status distribution provides visibility into the current state of orders and helps identify the volume of completed, active, and cancelled orders. This can help managers monitor the overall order pipeline and investigate cancellation patterns.
Second, revenue contribution varies across food categories. Categories generating a larger share of revenue can be monitored for inventory availability, promotions, and restaurant partnerships.
Third, the delayed-order analysis provides visibility into the relationship between delivery distance and delivery delays. Managers can use this information to identify delivery locations or distance ranges where operational performance may require attention.
Finally, the on-time delivery rate provides a direct measure of delivery performance. In the current dashboard, the on-time delivery rate is 20.6%, highlighting delivery timeliness as an important operational area to monitor.
Overall, the dashboard converts consumed streaming data into business-oriented information that can support monitoring of orders, revenue, and delivery operations.
